# 지도 표시 정책

Web Viewer의 지도 표현, 표시 파생 형상, 프레임 게시와 자원 수명을 규정한다. 지리 원본·프로젝트 형상은 문서·자료 계층이 소유한다.

## 기본 표시와 자산

- [Three.js Viewer](../../src/rendering/three-viewer-renderer.js)는 WebGL2 캔버스 하나로 지구본과 카메라를 제공한다. 장치 실제 DPR을 유지하며 카메라가 움직이면 GPU에서 투영을 갱신한다. 카메라 저장은 문서와 분리한다.
- [빌드](../../scripts/lib/globe-preview-assets.mjs)에서 정본 수역·영토를 삼각분할하고 공유 국경, 수계, 경위선, 선택 윤곽선을 생성한다. 별도의 고정 격자 피킹 파일은 생성하지 않는다. 형상은 월말 기준이며 경계 접합점, 구멍, 작은 섬과 날짜변경선·극지를 보존한다. 정본 좌표와 별개로 표시 자원을 관리한다.
- 영토 전송 패킷은 좌표 바이트 순서와 삼각형 인덱스 차분을 이용해 무손실 압축한다. 검증한 패킷은 기존 좌표, 삼각형 순서와 객체 식별자를 유지하는 GPU 버퍼 형식으로 한 번 복원한다. 압축 해제·바이너리 복원·공용 희소 공간 트리 준비와 수계 식별자 해석은 [패킷 Worker](../../src/rendering/workers/globe-packet-worker.js)가 담당하며 ArrayBuffer 소유권을 전송한다. 최초 표시는 해시·형식 검증을 통과한 자료의 디스크 캐시 저장을 기다리지 않는다.
- 기본·역사 국경, 기본·상세 하천, 경위선, 선택 윤곽선은 비트가 같은 고·저위 끝점 좌표를 공유하는 인덱스 패킷으로 생성한다. CPU 피킹은 동일한 좌표 사전을 직접 조회하고 GPU는 두 끝점 ID와 RGBA32F 좌표 텍스처를 사용한다. 텍스처 한도보다 큰 자료는 정확한 부분 사전으로 나누며 선분 순서·폭·소유자와 좌표 비트를 보존한다. 선분마다 좌표를 다시 펼친 배열은 만들지 않는다.
- 영토·수역 삼각형과 국경·하천·경위선·선택 윤곽선은 Worker에서 실제 3차원 중심점의 Morton 순서로 희소 계층형 공간 트리를 구성한다. 노드 범위는 정밀한 원래 프리미티브를 포함한다. 지평선·화면 절두체·선폭 여유 및 활성 소유자 마스크로 제외하며 선택한 프리미티브를 원래 순서로 압축 제출한다. 동일 가시 집합은 재사용하고 비활성 현대 영토와 기본 국경도 CPU에서 제외한다. 이 트리는 피킹과 공유하며 정본을 변경하지 않는다.
- 표시되는 육지의 외곽은 현재 표시된 영토 객체의 형상으로 결정한다. 물리 육지 형상은 첫 지도 이전에 표시하는 스켈레톤에 사용한다. 카메라 이동 시 영토 버퍼를 재사용한다. 공용 공간 트리는 패킷을 복원할 때 준비하고 함께 퇴출한다. 선택 윤곽선은 필요할 때 검증하고 읽는다.
- 초기 표시는 활성 영토와 필수 수역, 현재 표시 설정·확대 수준에 필요한 기본 국경·경위선·호수·기본 하천·지명 글꼴만 준비한다. 숨김 또는 확대 한도 밖 자원은 필요해질 때 읽는다. 기본 하천은 해당 시점·확대 수준에서 필요할 때 상주한다. 상세 하천은 정본 단계와 지역에 따라 준비한 패킷을 조작 종료 시 화면 범위에 따라 읽고, 예산을 초과하면 화면 밖에서 오래 사용하지 않은 항목부터 회수한다. 최소 표시 줌과 호수의 면적·폭 기준은 [공통 표시 정책](../../src/map/map-display-zoom.js)이 소유한다.
- 날짜가 바뀌어도 동일한 영토·윤곽선·공유 국경·수역은 콘텐츠가 같은 패킷을 공유한다. 활성 역사 국경 패킷 조합은 바이트·그룹 수 제한을 둔 연속 배치로 Worker에서 원래 순서대로 결합하고 공유 끝점 사전을 다시 사용한다. 동일 조합의 배치는 재사용하며 비활성 배치는 기존 캐시 예산에 따라 회수한다. Core에서 선택한 시점에 필요한 자산이 준비되면 [표시 조정자](../../src/rendering/viewer-rendering-domain.js)가 새 프레임을 게시한다. 역사 영토·국경과 물리 지도 CPU 캐시, 상주 메시 및 선택 윤곽선은 [공통 메모리 예산](../../src/rendering/render-cache-budget.js)에 따라 오래 사용하지 않은 비활성 자원을 회수한다. 현재·게시 대기·읽기 중인 필수 자원은 예산 초과 시에도 보존하고, GPU 자원은 새 프레임의 게시 승인 이후에 해제한다. 검증된 저장 패킷은 재사용한다.
- WebGL2 미지원 또는 복구 실패는 사용자에게 오류로 표시한다. context loss는 장치 자원에만 영향을 주며 카메라, 프로젝트, 유효한 다운로드·CPU 자료는 유지한다.

## 레이어와 상호작용

- 지도는 백지도 팔레트를 사용한다. 물리 수역은 바다색을 쓰고 영토 채우기 위에 표시한다. 경위선은 지도 표면에서 선택 제외 대상으로 처리하며 환경설정으로 표시를 바꿀 수 있다.
- 객체 색상 토글은 표시용 색상만 갱신한다. 불투명 중립색으로 바꿔도 저장한 고유색, 형상, 경계, 라벨과 선택은 유지한다.
- 주 선택, 보조 선택, 호버, 후보 순으로 강조한다. 선택 변경은 이전·현재 강조 슬롯만 갱신하고 공유 윤곽선은 활성 소유자의 선분 범위만 원래 순서대로 제출한다. 화면 좌표에서 현재 표시 자원의 인덱스를 조회해 Core의 객체 식별자 및 기존 상세 패널과 연결한다. 게시 승인된 프레임의 패킷 범위 계층과 공용 공간 트리로 후보를 선별하고 원래 정밀 삼각형·선분을 조회한다. 라벨 피킹은 충돌 격자의 스냅샷을 사용한다. 이전 클릭·호버 요청은 취소하고 뒤쪽 반구는 피킹에서 제외한다.
- 국명은 사전 계산한 앵커와 가까운 폴리곤의 짧은 변을 사용한다. 면적은 배치 우선순위에 쓰고, 글자 크기는 짧은 변과 확대 배율에 따른 상한으로 정한다. 도시는 기존 후보·최소 줌·존속기간을 적용한다. 화면 격자는 기존 우선순위·간격·유지 규칙에 맞춰 인접 라벨만 충돌 검사한다. Pretendard SDF 아틀라스는 연속 프레임에서 재사용한다. 예산을 초과하면 미사용 페이지부터 회수하고, 필요한 지명이 분산된 페이지는 기존 SDF 픽셀을 재배치해 페이지 수를 줄인다. 현재 후보는 예산만으로 생략하지 않는다. 국기는 상세정보에 표시한다. [지명 정책](places.md)이 지명 선정 및 존속기간을 소유한다.

## 자원 재사용과 표시 승인

- [공통 자원 의존성 정책](../../src/runtime/resource-dependency-policy.js)을 따른다. 입력 로딩, CPU 준비, GPU 업로드, 화면 표시의 변경을 구분한다. 날짜·뷰·프로젝트 세대·무관한 리비전 변경만으로 자원을 버리지 않는다.
- 시간별 존속·속성·형상 조회는 현재 시점으로 평가한 뒤 유효 결과를 비교한다. 이름·색 변경은 그 표시만 갱신하고, 동일한 형상·자료·자산은 재사용한다.
- 기존 자원 소유자가 검증된 콘텐츠 해시와 실제 준비 입력을 키로 관리한다. 복사된 객체의 identity나 프레임마다 전체 좌표 직렬화로 변경을 판정하지 않는다. context loss는 장치 자원만 무효화한다. 퇴출된 결과는 키가 같아도 다시 준비한다.
- 같은 콘텐츠를 기다리는 동시 요청은 저장 캐시 조회·검증과 전송·저장을 공유한다. 다운로드와 Worker 준비를 함께 제한하는 요청 수·추정 바이트 예산을 적용한다. 필수 대용량 작업은 단독으로 허용한다. 공통 상주 예산은 공유 CPU ArrayBuffer를 한 번만 계상하고 GPU 추정량을 별도로 합산하며 게시 승인 후 비활성 자원부터 회수한다. 개별 예산은 보조 제한이며 필수 활성 자료나 진행 중인 요청은 임의로 삭제하지 않는다. 취소는 요청별로 처리하며, 기다리는 요청이 모두 취소되면 내려받기 및 대기·실행 중인 패킷 복원을 중단한다. 새 날짜·프로젝트·표시 범위·선택이 이전 준비를 대체할 때 기존 게시 자원과 다른 소비자가 필요한 공유 자료는 보존한다.
- 비동기 준비 중에는 현재 표시 가능한 이전 결과를 유지한다. 삭제·숨김·현재 소유자 제거·빈 결과·프로젝트 교체는 이전 형상을 되살리는 근거가 될 수 없다.
- 계산 완료·패킷 생성·업로드 완료는 화면 표시 승인이 아니다. 현재 프로젝트·뷰·스타일·형상의 실제 WebGL2 draw로 게시를 확정한 뒤 교체 자원을 해제한다.
- 후보 draw 실패 시 유효한 이전 자원만 사용할 수 있다. 실패 프레임은 후보 승격이나 표시 완료를 승인하지 않는다. 기술 오류와 단계·자원 식별값을 해당 작업의 오류 경계로 전달한다.
- 동일한 입력으로 실패한 준비를 프레임마다 재시도하지 않는다. 취소·reset·dispose·오래된 응답은 현재 결과를 게시할 수 없다.

## 역사 자료

### 역사 형상 전송 최적화

정본 카탈로그의 형상 ID·GZIP·내용 SHA-256은 변경하지 않는다. 시작 묶음은 전체 구성원이 필요하고 캐시가 없는 경우에만 새로 받으며, 이미 보유한 묶음은 필요한 구성원만 해제한다. 역사 형상의 동일 좌표 및 공통 경계는 별도 정밀도 변경 없이, 인접 이력의 원본 JSON 바이트에 대한 무손실 copy/literal 차분으로 재사용한다. 빌드가 최대 48개 후보·8MiB 저장 입력·32MiB 해제 입력으로 제한한 선택적 보조 자료만 생성하고, 압축 크기 이득 및 원본 바이트 일치를 확인한 자료만 게시한다. 런타임은 기준 형상이 로컬에 있을 때만 단일 단계 차분을 사용하며, 결과 내용 해시가 일치하지 않으면 정본 GZIP으로 복구한다. 전 세계 형상의 공통 경계 정본을 새로 토폴로지화하지 않는다.

### 대규모 역사 자료 처리

Viewer의 역사 시점 카탈로그는 32개 고유 시점마다 전체 체크포인트를 두고 중간 시점의 활성 영토 슬롯·숨긴 기본 국경·역사 국경 순서 목록은 변경분 또는 더 작은 전체 목록으로 저장한다. 활성 슬롯의 지문으로 후보를 찾고 실제 목록을 대조하여 정확히 선택한다. 조회한 시점만 복원하며 복원 캐시는 최대 8개로 제한한다. 현재·게시 대기 시점은 각 표시 자원 소유자가 유지한다.

Core 준비 이력은 정규화된 날짜 문자열과 별도로 최소 달력 키만 색인하며, 변경 이벤트는 날짜·카탈로그 순번의 정렬된 배열로 관리한다. 연속 형상 존속 구간의 활성 객체 검색에는 최대 종료일을 가진 구간 트리를 사용한다. 원래 객체 순서 및 포함 경계는 유지한다. 동일한 불변 이력의 이벤트 없는 구간은 해석 결과를 공유하고, 큰 날짜 이동은 활성 객체 규모 및 이벤트 수 한도에 따라 재구성 경로를 택한다. JS 읽기 모델의 source-binding 구간 증명은 불변 구간 트리에서 변경된 잎만 갱신한다. Worker의 개별 요청에 대한 시간 진단은 상위 8개만 유지한다. 필수 활성 형상 및 원자적인 경계 갱신은 임의로 잘라내지 않는다.
