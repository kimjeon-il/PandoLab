# 지도 표시·LOD 정책

Web Viewer의 지도 표현, 표시 파생 형상, 프레임 게시와 자원 수명을 규정한다. 지리 원본·프로젝트 형상의 소유권은 문서·자료 계층에 있다.

## 카메라와 기본 표시

- 확대 상태와 저장 카메라는 MapLibre `zoom`을 사용하고 MapLibre 기본 줌 범위를 따른다. 전체 보기와 프로젝트·객체 범위는 MapLibre 카메라 맞춤을 사용한다.
- 국가명·국기는 MapLibre 줌 3부터, 도시 점·지명은 줌 3.5부터 표시한다. 초기 지도 표시 승인 전에는 심벌을 숨긴다.
- 강·호수는 바다와 동일한 표시 색상을 사용한다. 선택적 강·호수 타일은 MapLibre 줌 2·3·4·5부터 현재 화면 범위에 대해 단계별로 조회하고 표시한다. 날짜별 물리 수역은 정본 형상에 따라 표시한다.

- 위도 ±85°부터는 극지 Custom Layer가 정본 육지·수면·국가·강조·격자를 실제 구면 좌표로 표시한다. 일반 국경선은 양쪽 경로에서 같은 공유 경계 계산 결과를 사용한다. 타일 윤곽선도 ±85°에서 잘라 Mercator 한계 ±85.051129°의 끝점·연결선이 극점으로 늘어나지 않게 한다. 두 표시 경로의 인계 위도는 같게 유지하며, 극지 조회는 현재 날짜의 정본 형상을 사용한다.
- 극지 메시 준비는 형상 revision에 연결해 재사용하고, 현재 극지 준비·표시를 날짜 프레임 승인에 포함한다. 카메라 이동은 투영 행렬만 갱신한다.

## 정본과 표시 파생물

- 저장·면적·위상·검증·피킹은 정본 형상을 사용한다. 표시용 LOD를 정본에 역기록하지 않는다.
- Core의 현재 시점 형상을 GeoJSON source로 전달한다. scene 소유자는 형상·스타일·순서를 구분하고 바뀐 source 항목만 갱신한다. 공유 국경 계산은 기존 공통 Worker에서 수행하고 지리 좌표로 연결한다. 표준 선 표시를 위해 GPU 전용 stroke 패킷을 만들었다가 다시 GeoJSON으로 바꾸지 않는다. 사용되는 typed array의 소유권은 명시적으로 전달한다.
- 선택 형상의 정밀도를 배경 품질 예산 때문에 낮추지 않는다. 공유 경계는 양쪽에서 동일한 정점 선택과 연결 관계를 유지한다.
- 물리 육지의 표시 바탕은 현재 선택된 물리 형상에서 저장된 꼭짓점을 정확히 공유하는 성분별 합집합으로 내부 행정 경계를 제거한다. 원본·정본 물리 형상·지형 마스크는 그대로 유지한다. 등록된 기본 자료의 표시 파생물은 빌드 시 생성해 원본 해시·알고리즘 identity와 함께 게시하고, 등록되지 않은 동적 형상만 기존 Worker에서 준비한다. 실제 호수 구멍·분리된 섬·날짜변경선·극지 표현을 보존하며, 표시 소스의 배율별 일반화는 MapLibre가 수행한다.
- NE 기준 보정은 `T = max(T_ref × S_ref / S, T_min)` 원형 공식을 사용한다. 보정은 출처 identity와 실제 최대 배율의 CSS px/m 기준을 명시하며 고정 0.5px 상한으로 다시 자르지 않는다. LSIB와 NE의 위치 차이를 단순화 오차로 간주하거나 정점 수만 맞추지 않는다. 일부 구간의 보정 후보를 NE·혼합 출처 전체에 일괄 적용하지 않으며, 보정 도구의 결과와 제품에 실제 연결된 표시 경로를 구분한다.
- 접합점·다중 국가 교차점·구멍·날짜변경선·고위도 형상을 보호한다. MapLibre의 카메라·타일 투영에 정본 형상을 전달하며, 별도 장치 등급별 지리 형상 단순화나 과거 국가 메시 LOD 선택 경로를 두지 않는다.
- 파생 결과는 원본 콘텐츠·기하 리비전·알고리즘·배율 버킷·가시 범위를 식별한다. 오래된 프로젝트나 뷰의 완료 결과는 현재 화면을 교체할 수 없다. 준비와 업로드가 끝나기 전에 GPU 버퍼를 교체하지 않는다.

공통 기하 계산과 자료 생성용 메시 도구는 해당 도구의 소유권을 유지한다. Viewer 카메라·피킹·실제 프레임 승인은 [MapLibre renderer](../../src/rendering/maplibre-viewer-renderer.js)가 소유한다.

## 하나의 프레임·렌더러

- `maplibre-rendering-domain.js`가 source 준비와 라벨 게시 순서를 조정한다. 하나의 `MapVisualFrame`에 카메라 revision·viewport·safe inset·DPR·프로젝트 세대를 고정하며 투영은 실제 MapLibre 카메라를 사용한다.
- MapLibre의 source 처리 완료와 실제 render 이벤트가 현재 형상·카메라를 인증하고 동일 날짜의 symbol 소스가 반영된 뒤 표시 waiters를 게시한다. 날짜 source가 승인되기 전의 이전 프레임은 새 날짜 완료를 인증할 수 없다. 입력 좌표 역변환과 `queryRenderedFeatures` 결과는 기존 Core 선택·hover·겹친 객체 chooser로 전달한다.
- render DPR과 source DPR을 구분한다. backing 크기는 프레임의 render DPR, 원본 해상도 선택은 해당 source DPR을 사용한다.
- `maplibre-viewer-renderer.js`의 MapLibre Map 하나가 canvas와 WebGL context를 소유한다. 일반 폴리곤·선·선택은 그 source/layer를 공유하며 특수 합성 custom layer도 같은 MapLibre context와 투영을 사용한다. 선택 때문에 별도 canvas나 context를 만들지 않는다.
- 일반 지명·도시 점·국기는 MapLibre symbol/circle과 이미지 등록을 사용한다. 한국어·원어는 format 표현식으로 전달하고 충돌 배치는 MapLibre가 소유한다. SVG/DOM은 HUD·접근성·정보 패널에 사용한다. 지도 형상은 WebGL2만 표시하며 WebGL1·Canvas 대체 지구본은 두지 않는다. 미지원·복구 한도 초과는 지원 안내와 오류 상태로 종료하며 loading을 남기지 않는다.
- 일반 장치 상태와 context 복구는 MapLibre가 소유한다. custom layer는 자신이 변경한 blend·depth·stencil·VAO·buffer 상태를 복원하며 context가 바뀐 장치 자원을 재사용하지 않는다. 유효한 다운로드·CPU 결과와 Core 프로젝트·선택·카메라는 유지한다.
- 지도 생성 후 카메라는 MapLibre가 소유한다. 다른 계층은 불변 스냅샷을 읽고 이동 명령을 전달하며, 화면 크기 변경 시 상대 확대율을 유지한다. 저장된 보기 설정은 역사 문서와 분리한다.
- 선택적 외부 source와 확장 레이어는 역사 자료의 정본이나 선택 대상을 자동으로 만들지 않는다. 피킹은 지도 소유자가 등록한 source만 대상으로 하며, 외부 실패는 필수 프레임 실패와 구분한다.
- 선택적 확장 기능은 동기식 `install(map, scope)`에서 설치하고 해제 함수를 반환한다. 등록 도중 예외가 발생하면 새 MapLibre Source·Layer·Image는 취소·정리한다. 이벤트·컨트롤·Worker·GPU 자원처럼 MapLibre 레이어 목록으로 추적할 수 없는 항목은 획득 시 `scope.on`, `scope.addControl`, `scope.track` 또는 `scope.defer`로 해제를 등록한다. 확장 기능 오류가 Core·역사 프레임의 실패로 승격되지 않도록 한다.
- Viewer 제품의 투영은 지구본 하나만 지원한다. MapLibre 내부의 Mercator 타일 좌표계는 평면 지도 기능이 아니다. 별도 평면 지도 예제·테스트를 제품 지원으로 유지하지 않는다.
- 외부 스타일 전체 재구성 때는 현재 source 내용과 확장 기능의 설치·해제를 복원한다. custom layer는 MapLibre가 스타일 교체로 레이어를 버린 경우에도 자신의 장치 자원을 해제할 수 있어야 한다. 프로토콜 등록은 전역이고 요청과 해제 수명은 지도별로 분리한다. Custom Layer는 자기 VAO를 분리하고 MapLibre의 CustomLayerInterface 상태 복원 계약을 사용한다. 직전 native draw의 GL 상태를 매 프레임 동기 조회해 되돌리는 경로를 병행하지 않는다.

## 자원 재사용과 표시 승인

- [공통 자원 의존성 정책](../../src/runtime/resource-dependency-policy.js)을 따른다. 입력 로딩, CPU 준비, GPU 업로드, 화면 표시의 변경을 구분한다. 날짜·뷰·프로젝트 세대·무관한 리비전 변경만으로 자원을 버리지 않는다.
- 시간별 존속·속성·형상 조회는 현재 시점으로 평가한 뒤 유효 결과를 비교한다. 이름·색 변경은 그 표시만 갱신하고, 동일한 형상·자료·자산은 재사용한다.
- 기존 자원 소유자가 검증된 콘텐츠 해시와 실제 준비 입력을 키로 관리한다. 복사된 객체의 identity나 프레임마다 전체 좌표 직렬화로 변경을 판정하지 않는다. context loss는 장치 자원만 무효화한다. 퇴출된 결과는 키가 같아도 다시 준비한다.
- 비동기 준비 중에는 현재 표시 가능한 이전 결과를 유지한다. 삭제·숨김·현재 소유자 제거·빈 결과·프로젝트 교체는 이전 형상을 되살리는 근거가 될 수 없다.
- 계산 완료·패킷 생성·업로드 완료는 화면 표시 승인이 아니다. 현재 프로젝트·뷰·스타일·형상의 실제 WebGL2 draw로 게시를 확정한 뒤 교체 자원을 해제한다.
- 후보 draw 실패 시 유효한 이전 자원만 사용할 수 있다. 실패 프레임은 후보 승격이나 표시 완료를 승인하지 않는다. 기술 오류와 단계·자원 식별값을 해당 작업의 오류 경계로 전달한다.
- 동일한 입력으로 실패한 준비를 프레임마다 재시도하지 않는다. 취소·reset·dispose·오래된 응답은 현재 결과를 게시할 수 없다.

## 지도 시각 순서와 강조

- 경위선은 지도 바탕·국가·수계·국경 위, 선택·호버 강조와 지명·국기 아래에 표시한다. 극지에도 같은 순서를 적용하고 경위선 자체는 선택 대상으로 삼지 않는다.

- [layer-presentation.js](../../src/ui/layer-presentation.js)가 공통 시각 역할·순서의 단일 원본이다. Core의 영토 소유권과 MapLibre의 표시 source/layer를 구분한다.
- 단일 벡터 바탕 위에 국가/영토 채우기, 호수·강·국가 경계, 독립 overlay, 선택 강조, 라벨을 표시한다. 국가/영토 채우기는 physical water·수계·국경 아래에 두고 독립 overlay의 그룹/객체 순서는 정상 및 multiply 채우기와 선 사이에서도 유지한다. 수계·국경의 가독성을 유지하되 이전 GPU renderer의 stencil 픽셀 점유나 안티앨리어싱 구현을 병행하지 않는다.
- Viewer의 지도 바탕은 **단일 백지도**다. 정본 `physical-land` GeoJSON fill과 날짜별 수면·국경·국가·라벨·선택을 사용하며, 자연·고지도·DEM 전용 래스터 및 테마 프리셋을 사용하지 않는다.
- **객체 색상 표시**는 `layerPresentation.styles.objects.colorVisible`만 변경한다. 무채색 상태에서도 객체는 불투명 중립색으로 표시하며 폴리곤·국경·라벨·선택·고유 저장 색상은 보존한다. 색상 전환은 지형/역사 자료의 재로딩, 카메라 재설정, source 교체를 요구하지 않는다.
- 밝은 백지도의 육지·수면·선·라벨과 로딩 바탕은 `map-palette.js`가 제공한다. 앱 화면의 라이트·다크 모드는 지도 색상에 영향을 주지 않는다. `maplibre-map-style.js`와 `maplibre-style-controller.js`는 기존 MapLibre source와 레이어의 paint/layout만 갱신한다.
- 날짜 전환은 현재 날짜의 정본 국가·물리 육지·수역 벡터 source 로딩과 실제 WebGL render가 완료된 뒤 게시한다. 무관한 외부/선택적 레이어 타일의 상태는 날짜 승인 조건이 아니다. 물리 원자료와 역사적 형상·국기·수역 기록은 지도 테마 폐기와 별개로 보존한다.
- 비동기 결과가 기존 레이어 ID의 type을 바꾸지 않도록 한다. 지도 기본 바탕은 항상 `physical-land-fill` fill/physical-land로 유지한다. 실제 선택 feature의 정본 ref를 조회하고 중복 투명 source를 만들어 선택하지 않는다.
- 국가색과 선의 합성은 MapLibre fill/line-layer-blend를 사용한다. 선 폭·dash·cap·join·casing과 장치별 경계 커버리지는 MapLibre가 소유한다. 공유 국경의 정본 topology 계산은 기존 Core/Worker를 유지하고 결과를 GeoJSON 선으로 전달한다. 기본 시점의 공유 경계는 같은 Core 계산으로 빌드 시 생성할 수 있으며, catalog·알고리즘·WASM 식별값과 저장 바이트 해시를 묶어 배포한다. 실행 중 형상 지문이 모두 일치할 때만 재사용하고 달라진 형상은 기존 정본 계산으로 처리한다. 국가명 앵커도 기존 Worker 알고리즘을 빌드 때 수행하고 검증된 형상 지문과 함께 보관한다. 지문이 다르면 기존 Worker로 계산하며, 이름·국기·시점 유효성은 현재 날짜에 별도로 평가한다. Viewer 전용 합성 셰이더나 stroke framebuffer를 병행하지 않는다.
- 첫 지도의 시각적 로딩 스켈레톤은 화면 표시 장식이며 지도 데이터 레이어가 아니다. 현재 시점의 정본 육지·수면·국가·라벨 프레임이 승인되면 걷고, 선택적 외부 타일 전체의 완료를 기다리지 않는다. 기본 육지와 스켈레톤은 같은 정본 source를 참조한다. 양극 경위선은 로딩 바탕 위에서 같은 캔버스 애니메이션을 적용받는다. 벡터 표시 오류·미지원 시 오류 상태를 숨기지 않고, 사용자의 동작 줄이기 설정에서는 반짝임과 전환 애니메이션을 비활성화한다.
- 백지도 바탕은 고정이며 지정 색상이 없는 객체는 중립 바탕색을 사용한다. 전체 객체 채색을 끄더라도 저장된 고유 색은 유지하고 화면에만 불투명 중립색을 사용한다. 형상 가시성·피킹·경계·선택은 별도로 제어한다.
- 같은 객체의 강조 역할을 합친 뒤 주 선택 > 보조 선택 > hover > 후보 순으로 표시한다. 같은 ref의 선택과 hover를 중복 합성하지 않는다. 라벨 문자·국기는 재색칠하지 않고 별도 표식을 사용한다.
- 지도와 목록의 hover 출처를 구분해 늦은 leave가 다른 출처의 hover를 지우지 않게 한다. 사용자 선택색·채우기 0·선택 윤곽선 끄기 설정을 유지한다.
- 선 폭·dash·casing은 CSS px이며 CSS scale과 DPR 변환은 해당 경계에서 한 번만 적용한다. 객체별 opacity도 한 번만 곱한다. 스타일을 CSS에서 역추론해 GPU에 전달하지 않는다.
- 지도 선은 공통 stroke 스타일을 MapLibre의 CSS px 폭·dash·cap·join·casing 속성으로 전달한다. 지리 좌표와 연결 topology를 유지하며 view만 바뀔 때 source 형상을 다시 만들지 않는다. 국가 선택은 해당 객체의 형상만 강조한다.
- 국가명·국기의 유효한 지리 앵커는 양쪽 반구에 유지하며 MapLibre가 매 프레임 투영·가림·충돌을 처리한다. 카메라 이동만으로 현재 화면의 국가 앵커만 다시 뽑아 게시하지 않는다. 국기 이미지 ID는 로딩 전부터 안정적으로 지정하고 이미지 준비만으로 지명 source 전체를 다시 전송하지 않는다. 날짜 승인은 새 시점의 국가·수역·라벨 source와 실제 render를 기다리며, 선택적 국기 이미지 디코딩은 분리한다. 새 국기는 새 이미지 ID를 사용해 이전 날짜의 국기를 재사용하지 않는다. 도시·지명은 등급별 후보 상한을 적용하고 지명 선정·존속기간 규칙은 [지명 정책](places.md)이 소유한다.

## 품질·예산·벡터 표시

- 프레임 품질 평가는 실제 표시의 요청 대기·처리 시간을 포함한다. 숨김·유휴·자료 대기 시간은 상향 안정 시간에 넣지 않는다. 급확대에서는 목표 카메라와 필수 소스가 실제로 그려질 때까지 직전 프레임을 유지한다.
- 적응형 품질은 coarse/medium/high 단계다. 초기 기기 신호와 실제 프레임 p95/p99를 사용하며 사용자 에이전트 문자열만으로 고정하지 않는다.
- 선택은 실제 표시 자원과 MapLibre 투영을 사용한다. 라벨 후보 밀도, backing DPR, 프레임 업로드 예산을 구분한다.
- CPU 패킷·GPU 형상·수계 캐시는 바이트 예산과 LRU를 적용한다. 현재 보이는 자원과 선택 자원을 보호하고 비활성 자원부터 회수한다. 보호 자원만으로 예산을 넘으면 버리지 않고 pressure를 진단한다. 과거 시점의 정본 GPU 메시도 재사용하되 전체 관리 예산에서 실제 비기하·프레임버퍼 점유량과 보수적인 여유분을 제외하고 남은 공간에만 보관한다. 재방문 적중·건너뛴 업로드 바이트와 예산 부족 거부를 구분하여 기록하며, 공간이 부족한 저사양 기기에서는 캐시 미적중이 정상적인 보호 동작이다.
- 일반 타일·GPU 업로드와 타일 수명은 MapLibre가 소유한다. 앱은 source 변경·수계 pack 및 현재 사용 중인 특수 합성 자원의 수명을 관리하며 별도의 전역 GPU 업로드 조정기를 병행하지 않는다.
- 운영 Viewer는 DEM·자연색 타일 데이터 및 렌더링 매니페스트를 읽지 않는다. 라이브러리 내부의 테마 전용 파생 데이터와 생성기를 폐기하되, 이전 공개 Viewer가 아직 접근할 수 있는 버전별 외부 타일은 기존 배포 소비가 종료될 때까지 별도로 보존한다.

- 기기 유형(모바일·데스크톱) 자체는 초기 coarse 판정 근거가 아니다. 알려진 RAM 4GB 이하·논리 코어 4개 이하·데이터 절약이면 coarse, RAM 8GB 이상과 논리 코어 8개 이상이 모두 알려지면 high, 나머지(정보 없음 포함)는 medium이다. 모든 품질에서 기기 실제 DPR을 유지하며 모바일 2배·데스크톱 3배 같은 고정 상한이나 성능 상태에 따른 자동 해상도 축소를 두지 않는다. 활성 프레임의 p95·관리 메모리 압박에 따른 등급 조절은 라벨 후보·캐시 예산에만 적용한다. 선택적 화면 MSAA·색상 후처리는 조작 동안 유예할 수 있다. 도시·지명 후보 상한은 128/256/512, 별도 출처 보정이 없는 공통 벡터 geometry의 기본 오차 예산은 0.5 CSS px다. 정본 경계·타일 포함·피킹은 낮추지 않는다.
- 최근 60개 활성 표시 프레임을 20개마다 평가한다. 숨김·유휴·자료 대기를 제외하고 CPU와 실제 프레임 간격을 사용한다. p95 40ms 초과 두 창이면 하향하며, 상향은 25ms 미만 여섯 창·15초 안정·조작 종료·관리 메모리 여유를 모두 요구한다. 평가용 유휴 프레임을 생성하지 않는다.
- GPU 관리 목표는 64/128/256 MiB, CPU 파생 목표는 96/192/256 MiB다. 추적 가능한 자원·좌표 payload를 관리하는 목표이며 전체 VRAM 조회나 실기기 성능 보장이 아니다. 화면 파생은 제한된 메모리 캐시만 사용하고 품질별 파일·자료 판본을 만들지 않는다.

## Worker와 진단

- 무거운 CPU 요청은 `src/runtime/worker-rpc.js`와 Worker host의 공통 RPC를 사용한다. 요청 ID·timeout·취소·crash·오래된 결과 거부·오류 형식을 기능마다 재구현하지 않는다.
- job scheduler는 우선순위·동시성·latest-wins를, RPC는 전송 수명과 결과 정합성을 소유한다. 논리 작업 키와 입력/수용 리비전을 구분한다.
- 상태·대형 캐시를 소유하는 수계·자료 Worker는 전용으로 유지한다. 독립 계산만 제한된 동시성으로 처리하며 Worker 개수 자체를 성능 목표로 삼지 않는다. 전용 transport 예외는 소유 코드에 이유를 명시한다.
- 진단값은 세션 정보이며 프로젝트에 저장하지 않는다. 동일 기기·프로젝트·작업의 cold/warm 조건을 구분해 측정한다. 통계적 진단 임계값을 기능 차단 상한으로 사용하지 않는다. 과거 측정치를 현재 성능 보장으로 전용하지 않는다.
- 검증은 [검증 정책](validation.md)의 영향받은 실제 Viewer 표시·미지원 안내·context 복구 범위로 제한한다. 표시 성공은 원자료 GIS 정확성의 검수 완료를 뜻하지 않는다.
