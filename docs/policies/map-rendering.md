# 지도 표시 정책

Web Viewer의 지도 표현, 표시 파생 형상, 프레임 게시와 자원 수명을 규정한다. 지리 원본·프로젝트 형상은 문서·자료 계층이 소유한다.

## 기본 표시와 자산

- [Three.js Viewer](../../src/rendering/three-viewer-renderer.js)는 WebGL2 캔버스 하나로 지구본과 카메라를 제공한다. 장치 실제 DPR을 유지하며 카메라가 움직이면 GPU에서 투영을 갱신한다. 카메라 저장은 문서와 분리한다.
- [빌드](../../scripts/lib/globe-preview-assets.mjs)에서 정본 수역·영토를 삼각분할하고 공유 국경, 수계, 경위선, 선택 윤곽선을 생성한다. 별도의 고정 격자 피킹 파일은 생성하지 않는다. 형상은 월말 기준이며 경계 접합점, 구멍, 작은 섬과 날짜변경선·극지를 보존한다. 정본 좌표와 별개로 표시 자원을 관리한다.
- 표시용 [LOD 정책](../../src/rendering/globe-lod.js)은 영토·수역·호수의 구면 삼각분할과 기본·역사 국경·선택 윤곽선을 같은 단계로 준비한다. 세 단계는 최대 구면 변 4°/1.5°/0.499°와 서로 다른 Cartesian 공간 청크 크기·격자 분할을 사용한다. 세분화 전 정본 다각형의 경계 정점·구멍·소유자 및 역사 슬롯을 유지하고, 하천의 낮은 단계는 같은 소유자의 연속 선분에서만 오차와 선폭 차이를 제한해 축약한다. 접합점·패킷 사이 공유 끝점은 보호한다. 정확 단계의 좌표는 유지한다. 실제 DPR·확대·기울기에서 추정한 화면 오차와 히스테리시스로 한 단계를 고르며, 이 추정은 정본 경계의 절대 픽셀 오차 인증이 아니다. 표시 단계마다 별도 공간 색인을 지연 생성하고 선택한 단계의 자원만 내려받으며 서로 다른 단계의 준비·GPU 배치·피킹을 혼합하지 않는다. 누락된 LOD 또는 소유자 범위가 다른 표시 자산은 게시하지 않는다. 구형 표시 manifest는 정확 단계로 읽는다. 원본 자료 pin과 Core 정본은 변경하지 않는다. 이 단계만으로 초고밀도 정본 경계 정점이나 활성 프리미티브의 수가 절대 상한을 갖지는 않는다.
- [활성 표시 예산](../../src/rendering/globe-active-budget.js)은 영토·국경선·필수 수역·호수·기본 하천의 청크를 합산해 다운로드 전 삼각형·선분·Draw Call·청크 수와 CPU/GPU 추정 바이트를 검사한다. 장치 메모리와 품질 단계에 따른 목표를 넘으면 같은 시점의 더 낮은 LOD를 선택하며, 영토와 수계를 서로 다른 단계로 승인하지 않는다. 목표를 만족할 수 없더라도 절대 계획 상한을 넘는 필수 형상을 누락하여 게시하지 않는다. 최저 LOD까지 상한을 넘으면 복구 가능한 예산 오류로 처리한다. 기존 게시 자료와 교체 계획의 중복 키를 제외한 동시 상주 추정량도 제한한다. 여유 범위의 패킷은 전체 여유 계획이 목표에 맞을 때만 활성화한다. 필수 계획 승인 후 선택 윤곽선(주 선택 우선)과 상세 하천(카메라 근접 우선)은 같은 잔여 예산에서 청크 단위로 허용하고, 지명 후보 수·래스터 면적도 제한한다. WebGL 제출 전 실제 활성 삼각형·선분과 지명 포함 Draw Call을 재확인한다. 보호 중인 CPU 공유 버퍼·GPU 및 기타 바이트는 증분 원장에 기록한다. 메모리 압력이 높은 동안 선택 자원과 선제 로딩을 억제하고 여유가 회복될 때 재평가한다. 필수 다운로드의 예외 작업 예약량도 기존 pendingBytes 범위의 초과 여유로 제한한다. 실제 드라이버 메모리나 모든 동기 GPU 할당의 절대 상한은 아니며, 정본 경계의 추가 단순화는 별도 구현 대상이다. [프레임별 GPU 예산](../../src/rendering/globe-gpu-frame-budget.js)은 기본 생성 6 MiB·8개 작업, 업로드 8 MiB·6개 작업, 동적 압축 갱신 2 MiB를 기준으로 장치 메모리에 따라 조정한다. 분할할 수 없는 개별 GPU 자원은 별도 단독 작업 상한 안에서만 허용한다. 필수 메시·텍스처는 여러 프레임에 걸쳐 비공개 렌더 타깃에서 준비하고, 선분의 큰 변경 범위는 커서를 유지해 제한된 바이트·구간씩 전송한다. 압축 인덱스 갱신이 예산에 맞지 않으면 이미 준비된 원본 인덱스로 정확한 형상을 제출한다. 모든 필수 형상이 준비될 때까지 새 화면을 승인하지 않으며 준비 중·취소된 메시와 이전 게시 메시의 수명을 분리한다. 상세 하천·경위선·지명·윤곽선은 준비된 것만 표시하고 실제 게시 가능한 지명·상세 하천만 피킹 대상으로 삼는다. 예산은 작업 단위의 추정치이며 GPU 드라이버 시간·내부 호출 수에 대한 절대 보증은 아니다.
- 카메라의 실제 제스처·관성 이동 동안에는 정상 LOD의 히스테리시스를 유지하면서 화면 오차 허용치만 네 배로 완화한다(정지 기준 0.6px, 이동 기준 2.4px; 추정치). 극고배율에서는 정확 단계를 유지한다. 지명 후보 상한을 절반으로 줄이고 상세 하천의 신규 표시·준비를 정지 후까지 보류한다. 이동 종료 시 정상 기준으로 다시 평가하며, 더 정밀한 형상은 기존 전환 및 프레임별 GPU 예산 안에서 준비한다. 새 계획이 준비 중이면 같은 역사 시점·물리 자료·영토 가시성 및 한 LOD의 게시된 형상이 현재 화면 전체를 덮고 절대 예산에 맞을 때만 현재 카메라로 다시 표시한다. 피킹은 실제 제출한 계획을 따른다. 완전한 형상이 없으면 이전 승인 프레임을 유지하되 관성 계산은 멈추지 않는다. 완전한 기존 형상이 있을 때 추가 정밀도 준비 실패는 지도 전체 실패로 처리하지 않는다. 초기·시간축 게시 계약은 그대로 유지한다.
- 영토·수역 전송 패킷은 좌표 바이트 순서와 삼각형 인덱스 차분을 이용해 무손실 압축한다. 기본·역사 영토, 필수 수역 및 호수는 빌드 시 Morton 순서의 공간 청크로 생성한다. 고·저위 좌표 비트와 서로 다른 표시 소유자의 겹침 순서는 보존하며, 동일 소유자의 프리미티브만 공간적으로 재배열한다. 기본·역사 국경선 및 기본·상세 하천에도 동일한 공간 분할을 적용한다. 청크별 보수적 3차원 범위·소유자 목록·공간 셀을 기록하고, 큰 단일 프리미티브를 제외하면 떨어진 공간을 한 청크에 합치지 않는다. 중복되는 전 세계 단일 전송 패킷을 함께 생성하지 않는다. 검증한 패킷은 청크에 기록된 좌표·프리미티브·객체 식별자를 유지하는 GPU 버퍼 형식으로 한 번 복원한다. 압축 해제·바이너리 복원·공용 희소 공간 트리 준비와 수계 식별자 해석은 [패킷 Worker](../../src/rendering/workers/globe-packet-worker.js)가 담당하며 ArrayBuffer 소유권을 전송한다. 최초 표시는 해시·형식 검증을 통과한 자료의 디스크 캐시 저장을 기다리지 않는다.
- 기본·역사 국경, 기본·상세 하천, 경위선, 선택 윤곽선은 비트가 같은 고·저위 끝점 좌표를 공유하는 인덱스 패킷으로 생성한다. CPU 피킹은 동일한 좌표 사전을 직접 조회하고 GPU는 대규모 배치에서 두 끝점 ID와 RGBA32F 좌표 텍스처를 사용하며 2의 거듭제곱 행 폭으로 주소 나눗셈을 제거한다. 2048개 이하의 소규모 선분 배치에는 동일 고·저위 좌표 속성을 직접 사용해 텍스처 조회를 생략한다. 텍스처 한도보다 큰 자료는 정확한 부분 사전으로 나누며 선분 순서·폭·소유자와 좌표 비트를 보존한다. 대규모 정본 패킷에서는 선분마다 좌표를 다시 펼친 배열을 만들지 않는다.
- 영토·수역 삼각형과 국경·하천·경위선·선택 윤곽선은 Worker에서 실제 3차원 중심점의 Morton 순서로 희소 계층형 공간 트리를 구성한다. 노드 범위는 정밀한 원래 프리미티브를 포함한다. 지평선·화면 절두체·선폭 여유 및 활성 소유자 마스크로 제외하며 선택한 프리미티브를 원래 순서로 압축 제출한다. 동일 가시 집합은 재사용하고 비활성 현대 영토와 기본 국경도 CPU에서 제외한다. 같은 좌표 사전을 공유하는 연속 공간 부분은 동일 재질의 인스턴스 제출로 통합하며 원래 순서를 유지한다. 이전 제출과 달라진 목적지 구간만 동적 인덱스·속성 버퍼에 복사하고 업로드한다. 소유자별 가시성 변경 번호와 재사용 작업 배열을 사용한다. 연속된 가시 인덱스 범위가 두 개 이하이면 원본 인덱스를 직접 제출하고, 그보다 복잡하면 제한된 수의 원본 블록별 동적 인덱스 버퍼에 압축한다. 블록 용량은 가시 수에 따라 확장·축소하며 같은 재질·공간 셀의 연속 소형 메시만 제한된 크기로 결합하여 서로 다른 소유자·레이어의 순서를 보존한다. 이 트리는 피킹과 공유하며 정본을 변경하지 않는다.
- 표시되는 육지의 외곽은 현재 표시된 영토 객체의 형상으로 결정한다. 물리 육지 형상은 첫 지도 이전에 표시하는 스켈레톤에 사용한다. 카메라 이동 시 영토 버퍼를 재사용한다. 공용 공간 트리는 패킷을 복원할 때 준비하고 함께 퇴출한다. 선택 윤곽선은 공유 경계의 정확한 고·저위 좌표를 유지하는 소형 공간 청크로 생성하며 청크별 소유자 목록을 기록한다. 선택·호버 대상의 소유자 역색인과 현재 화면 범위로 필요한 원본 청크만 검증하고 읽는다. 기존 단일 패킷은 호환 경로로 읽을 수 있다.
- 초기 표시는 현재 카메라에 필요한 활성 기본·역사 영토, 기본·역사 국경선, 필수 수역 및 표시 확대 수준의 호수·기본 하천 청크와 필요한 경위선·지명 글꼴을 준비한다. 공통 청크 카탈로그의 3차원 범위 계층을 사용하며 화면 범위와 활성 소유자, 확대 수준, 선폭 여유를 함께 적용한다. 화면 밖 청크는 읽지 않으며 새 뷰에 필요한 청크가 없으면 선택된 표시 단계의 필수 형상이 도착할 때까지 이전 승인 프레임을 유지한다. 첫 게시 이후 주변 화면 여유 범위의 청크를 준비하고 공통 예산에 따라 회수한다. 숨김 또는 확대 한도 밖 자원은 필요해질 때 읽는다. 기본 하천은 해당 시점·확대 수준에서 필요할 때 상주한다. 상세 하천도 동일한 공간 색인으로 가시 청크를 읽고, 예산을 초과하면 화면 밖에서 오래 사용하지 않은 항목부터 회수한다. 최소 표시 줌과 호수의 면적·폭 기준은 [공통 표시 정책](../../src/map/map-display-zoom.js)이 소유한다.
- 역사 공간 카탈로그는 슬롯·국경 그룹 번호·물리 자료 식별값·시간축을 보존한 경량 색인과 해시로 검증하는 별도 페이지로 생성한다. 역사 영토·윤곽선 및 국경 페이지는 인접 3차원 위치별로 묶고 기본 64개 행 및 약 256 KiB를 목표로 분리한다(단일 대형 LOD 계열은 따로 보존). 모든 LOD를 포함한 보수적 범위와 현재 역사 슬롯·국경 그룹·화면 여유 범위가 교차하는 페이지만 읽는다. 현재·역사 물리 자료의 색인은 식별값·수역 객체 정보와 별도 공간 페이지 참조만 보존한다. 필수 수역·호수·기본 하천·상세 하천의 청크 목록은 같은 레이어·LOD·최소 확대 수준의 인접 공간 페이지(128개 행·약 256 KiB 목표)로 분리한다. 필요한 화면·레이어·확대 수준에 맞는 페이지를 선택하며 상세 하천 목록은 카메라 정지 후 별도 선택 예산 안에서 읽는다. 페이지 안의 원래 청크 순번·키와 수역 식별값을 유지하고 같은 내용의 수계 페이지는 다른 역사 시점에서도 재사용한다. 실제 형상 계획은 필요한 페이지가 모두 검증된 뒤 승인하며 기존 화면과 피킹을 보존한다. 페이지 요청은 공용 Worker·다운로드 예산·취소 및 바이트 제한 LRU를 사용한다. 필수 공간 색인의 동시 준비 추정량을 전체 렌더 예산의 1/4 이내로 제한하며 초과 시 부분 지도를 승인하지 않는다. 활성 색인은 전체 역사 카탈로그와 독립적으로 회수하며 원래 슬롯·그룹·패킷 키를 유지한다. 인접 시점의 페이지 선제 읽기도 기존 선제 로딩 예산에 포함한다. 생성·게시 검증은 색인과 모든 페이지의 범위·LOD·소속 및 해시 영수증을 확인한다.
- 날짜가 바뀌어도 동일한 영토·윤곽선·공유 국경·수역은 콘텐츠가 같은 패킷을 공유한다. 활성 역사 국경 청크는 시점별로 안정적인 공간 셀과 바이트·그룹 수 제한을 적용한 배치로 Worker에서 결합하고 공유 끝점 사전을 다시 사용한다. 화면 이동 시 동일 공간 배치 ID를 유지하며 비활성 배치는 기존 캐시 예산에 따라 회수한다. 배치 전체의 임시 메모리를 먼저 예약하고 검증된 압축 바이트 소유권을 Worker로 이전한다. 원본을 하나씩 해제해 결합 사전에 누적하므로 복원한 원본 국경 패킷을 CPU 캐시에 보존하거나 Worker로 복제하지 않는다. 저장 캐시와 필수 결합 작업 공간은 유지한다. Core에서 선택한 시점에 필요한 자산이 준비되면 [표시 조정자](../../src/rendering/viewer-rendering-domain.js)가 새 프레임을 게시한다. 역사 영토·국경과 물리 지도 CPU 캐시, 상주 메시 및 선택 윤곽선은 [공통 메모리 예산](../../src/rendering/render-cache-budget.js)에 따라 오래 사용하지 않은 비활성 자원을 회수한다. 현재·게시 대기·읽기 중인 이미 승인된 필수 자원은 보존하고, 새 계획은 활성 및 전환 예산으로 승인하며 GPU 자원은 새 프레임의 게시 승인 이후에 해제한다. 검증된 저장 패킷은 재사용한다.
- WebGL2 미지원 또는 복구 실패는 사용자에게 오류로 표시한다. context loss는 장치 자원에만 영향을 주며 카메라, 프로젝트, 유효한 다운로드·CPU 자료는 유지한다.

## 레이어와 상호작용

- 지도는 백지도 팔레트를 사용한다. 물리 수역은 바다색을 쓰고 영토 채우기 위에 표시한다. 경위선은 지도 표면에서 선택 제외 대상으로 처리하며 환경설정으로 표시를 바꿀 수 있다.
- 객체 색상 토글은 표시용 색상만 갱신한다. 국가 기본 색상·가시성, 국가 강조 채우기, 윤곽선 스타일, 수계 강조·가시성, 지명 설정, 렌더 품질의 무효화 경로를 분리한다. 동일 내용의 표시 설정 및 선택 역할은 재사용하며 개별 국가 숨김 변경은 해당 슬롯만 갱신한다. 선폭·색상 등 재질 변경은 해당 재질의 uniform에 적용하고 무관한 국가·수계·라벨을 재생성하지 않는다. 전체 및 부분 색상 변경 기록은 실제 GPU 텍스처 업로드 완료까지 누적 유지하며 지연된 프레임이 후속 부분 갱신을 덮어쓰지 않는다. 불투명 중립색으로 바꿔도 저장한 고유색, 형상, 경계, 라벨과 선택은 유지한다.
- 주 선택, 보조 선택, 호버, 후보 순으로 강조한다. 선택 변경은 이전·현재 강조 슬롯만 갱신하고 공유 윤곽선은 활성 소유자의 선분 범위만 원래 순서대로 제출한다. 소유자-청크 역색인은 패킷 Worker에서 준비한다. 변경된 청크만 갱신하고 소유자 집합이 같은 부분 좌표 사전을 청크별 최대 두 개 재사용한다. 작은 윤곽선은 부분 사전을 만들지 않고 정확한 원본 끝점에서 직접 속성을 채운다. 화면에 제출할 선분이 있을 때 활성 소유자에 해당하는 고·저위 좌표 사전만 준비하고, 표시 인스턴스 수에 따라 버퍼를 확장·축소한다. 화면 밖·비활성 청크는 상위 공용 패킷이 활성 상태여도 독립적으로 회수할 수 있다. 승인 후 대기 청크는 윤곽선 예산의 1/4 및 64개를 상한으로 LRU 회수하며, 전체 상주 예산에도 포함한다. 화면 좌표에서 현재 표시 자원의 인덱스를 조회해 Core의 객체 식별자 및 기존 상세 패널과 연결한다. 화면 좌표 변환은 실제 게시된 카메라를 사용하며 뷰포트가 달라져 이전 화면의 좌표를 보증할 수 없으면 피킹을 차단한다. 게시 승인된 프레임의 패킷 범위 계층과 공용 공간 트리로 후보를 선별하고 게시된 표시 단계의 삼각형·선분을 조회한다. 라벨 피킹은 충돌 격자의 스냅샷을 사용한다. 이전 클릭·호버 요청은 취소하고 뒤쪽 반구는 피킹에서 제외한다. 정확 피킹 및 패킷 후보 순회를 한 요청의 3ms 목표 시간 조각으로 분할하여 입력 이벤트에 제어권을 돌려주고 재개 시 승인 프레임과 취소 상태를 확인한다.
- 국명은 사전 계산한 앵커와 가까운 폴리곤의 짧은 변을 사용한다. 면적은 배치 우선순위에 쓰고, 글자 크기는 짧은 변과 확대 배율에 따른 상한으로 정한다. 도시는 기존 후보·최소 줌·존속기간을 적용한다. 지명 앵커는 좌표가 바뀔 때만 구면 벡터를 만들고 계층형 공간 인덱스로 가시 후보를 선별한다. 화면 격자는 기존 우선순위·간격·유지 규칙에 맞춰 인접 라벨만 검사하며 같은 후보 쌍을 한 번만 비교한다. 글꼴 측정은 별도 제한 캐시로 재사용하고, 충돌 배치까지 통과한 라벨에 한해 Pretendard SDF를 생성한다. 글꼴 측정은 문서에서 유지하고 동일 Pretendard Variable 글꼴을 전용 Worker에 로드한다. 두 글꼴 굵기의 대표 래스터 및 글자 측정 결과와 개별 지명의 줄 단위 메트릭이 일치하면 마스크 래스터부터 거리장까지 Worker에서 수행한다. 호환성이 확인되지 않으면 문서의 마스크를 전달해 Worker에서 거리장을 계산하고 Worker 자체가 실패하면 지명별로 입력 처리를 양보하는 제한된 로컬 복구를 사용한다. 거리장 임시 배열은 동일 배치 내에서 재사용한다. 소규모 제한 배치와 최신 가시 후보 취소를 적용하며 Worker 오류 시 동일 알고리즘의 로컬 경로로 복구한다. 최초·역사 전환 프레임에는 필수 지명의 SDF 준비를 장면 활성화 전에 끝내고 동일 가시 배치는 Worker 응답마다 재계산하지 않는다. 일반 카메라 이동에서는 준비된 지명만 표시·피킹한다. 이미 업로드된 단일 채널 아틀라스와 배치 텍스처는 Three.js의 직사각형 복사 API로 변경 영역만 갱신한다. 최초 업로드·컨텍스트 복구·넓은 변경 영역은 전체 업로드한다. 수계 강조의 단일 채널 텍스처도 변경 슬롯을 행별 직사각형으로 결합하여 부분 전송한다. 최초·복구·넓은 변경은 전체 전송하고 수역별 강조는 변경 객체에만 적용한다. 페이지별 인스턴스 배치는 실제 표시 수에 따라 확장·축소하며 장치 텍스처 크기를 넘는 경우 여러 배치로 나눈다. 예산을 초과하면 화면에 쓰지 않는 페이지부터 회수한다. 아틀라스는 게시·준비 중인 배치가 참조하지 않는 기존 지명 영역을 재사용하고, 필요한 지명이 분산된 경우 임시 예산을 확보한 뒤 같은 종류의 두 페이지를 한 번에 재배치한다. 배치된 지명을 예산만으로 생략하지 않는다. 국기는 상세정보에 표시한다. [지명 정책](places.md)이 지명 선정 및 존속기간을 소유한다.

## 자원 재사용과 표시 승인

- [공통 자원 의존성 정책](../../src/runtime/resource-dependency-policy.js)을 따른다. 입력 로딩, CPU 준비, GPU 업로드, 화면 표시의 변경을 구분한다. 날짜·뷰·프로젝트 세대·무관한 리비전 변경만으로 자원을 버리지 않는다.
- 시간별 존속·속성·형상 조회는 현재 시점으로 평가한다. 승인된 Core 배열의 변경 영수증과 유효기간·국명 전환 경계 색인을 사용해 영향을 받는 객체 및 색상 상속 종속 객체만 다시 계산한다. 영수증이 없으면 실제 행 identity 비교로 복구하고 명시적인 전체 표시 설정 변경은 전체 갱신을 허용한다. 국가·장소 후보 공간 색인과 후보 목록의 무효화는 별도로 유지한다. 같은 카메라·뷰포트·시점·레이어 조건의 공간 청크 계획, 절두체 판정 및 청크 ID 집합을 재사용하며, 불변 장소 기록의 동일 이름 구간은 Core의 이름 해석 결과를 재사용한다.
- 기존 자원 소유자가 검증된 콘텐츠 해시와 실제 준비 입력을 키로 관리한다. 복사된 객체의 identity나 프레임마다 전체 좌표 직렬화로 변경을 판정하지 않는다. context loss는 장치 자원만 무효화한다. 퇴출된 결과는 키가 같아도 다시 준비한다.
- 같은 콘텐츠를 기다리는 동시 요청은 저장 캐시 조회·검증과 전송·저장을 공유한다. 카메라·시점 변경 시 공통 청크의 대기자를 유지하고 선택적 요청을 필수 요청으로 승격한다. 선택적 준비 실패는 이후 필수 준비를 차단하지 않으며, 현재 필요한 필수 청크의 실패는 재시도 가능한 오류로 전달한다. 다운로드와 Worker 준비를 함께 제한하는 요청 수·추정 바이트 예산을 적용한다. 지도 패킷과 SDF의 stateless Worker는 공통 CPU 실행 한도를 사용한다. 장치 메모리·CPU 힌트에 따른 최대 1~3개의 실행 슬롯 안에서 메모리 압력과 대기 시간에 따라 동시성을 조정하며 취소된 작업의 Worker만 종료한다. 공유 패킷의 실제 소비자가 요청하면 대기 중 우선순위를 승격한다. 동등 우선순위의 작은 작업은 제한적으로 선행할 수 있고 낮은 우선순위 추측 작업은 전경 작업이 없을 때만 단독 시작한다. 필수 대용량 작업은 단독으로 허용한다. 공통 상주 예산은 공유 CPU ArrayBuffer의 참조 수와 GPU 추정량을 자원 변경 시 증분 갱신하며 비활성 자원부터 회수한다. 압축 입력·복원/공간 트리 작업 공간·Worker 전달·SDF 마스크 및 거리장·GPU 배치/인덱스 재할당의 임시 비용은 작업 전에 추정 예약하고 완료·취소 시 해제한다. 디스크 캐시 저장 대기량은 별도의 제한 아래 같은 예산에 포함하며, 여유가 부족하면 선택적 저장을 건너뛴다. 이미 승인된 필수 활성 자료는 보존하며, 예산을 넘는 필수 비동기 요청은 설정된 초과 여유 범위에서 한 번에 하나만 실행할 수 있다. 브라우저·GPU 할당량은 추정값이며 절대 메모리 상한으로 간주하지 않는다. 변경된 윤곽선 청크만 원장을 수정하고 예산 초과 시에만 해당 대기 후보를 정렬한다. 메시·라벨·하천의 독립적인 자원 소유자는 실제 변경된 경우에만 원장 스냅샷을 갱신한다. 개별 예산은 보조 제한이며 필수 활성 자료나 진행 중인 요청은 임의로 삭제하지 않는다. 취소는 요청별로 처리하며, 기다리는 요청이 모두 취소되면 내려받기 및 대기·실행 중인 패킷 복원을 중단한다. 새 날짜·프로젝트·표시 범위·선택이 이전 준비를 대체할 때 기존 게시 자원과 다른 소비자가 필요한 공유 자료는 보존한다.
- 비동기 준비 중에는 현재 표시 가능한 이전 결과를 유지한다. 삭제·숨김·현재 소유자 제거·빈 결과·프로젝트 교체는 이전 형상을 되살리는 근거가 될 수 없다.
- 계산 완료·패킷 생성·업로드 완료는 화면 표시 승인이 아니다. 현재 프로젝트·뷰·스타일·형상의 승인 조건을 draw 전에 확인한다. 실제 WebGL2 draw 후 승인된 카메라·피킹 상태를 먼저 게시한 뒤 전환 완료 콜백을 전달하고 교체 자원을 해제한다.
- 후보 draw 실패 시 유효한 이전 자원만 사용할 수 있다. 실패 프레임은 후보 승격이나 표시 완료를 승인하지 않는다. 기술 오류와 단계·자원 식별값을 해당 작업의 오류 경계로 전달한다.
- 동일한 입력으로 실패한 준비를 프레임마다 재시도하지 않는다. 취소·reset·dispose·오래된 응답은 현재 결과를 게시할 수 없다.

## 역사 자료

### 역사 형상 전송 최적화

정본 카탈로그의 형상 ID·GZIP·내용 SHA-256은 변경하지 않는다. 시작 묶음은 전체 구성원이 필요하고 캐시가 없는 경우에만 새로 받으며, 이미 보유한 묶음은 필요한 구성원만 해제한다. 역사 형상의 동일 좌표 및 공통 경계는 별도 정밀도 변경 없이, 인접 이력의 원본 JSON 바이트에 대한 무손실 copy/literal 차분으로 재사용한다. 빌드가 최대 48개 후보·8MiB 저장 입력·32MiB 해제 입력으로 제한한 선택적 보조 자료만 생성하고, 압축 크기 이득 및 원본 바이트 일치를 확인한 자료만 게시한다. 런타임은 기준 형상이 로컬에 있을 때만 단일 단계 차분을 사용하며, 결과 내용 해시가 일치하지 않으면 정본 GZIP으로 복구한다. 전 세계 형상의 공통 경계 정본을 새로 토폴로지화하지 않는다.

### 대규모 역사 자료 처리

Viewer의 역사 시점·역사 영토/국경 청크·추가 물리 시점 카탈로그는 해시가 검증되는 별도의 압축 자산으로 게시하여 현대 기본 지도 초기 목록에서 분리한다. 필요한 역사 시점 조회 또는 제한된 유휴 선제 준비 시 읽는다. 역사 시점 카탈로그는 32개 고유 시점마다 전체 체크포인트를 두고 중간 시점의 활성 영토 슬롯·숨긴 기본 국경·역사 국경 순서 목록은 변경분 또는 더 작은 전체 목록으로 저장한다. 활성 슬롯의 지문으로 후보를 찾고 실제 목록을 대조하여 정확히 선택한다. 조회한 시점만 복원하며 복원 캐시는 최대 8개로 제한한다. 현재·게시 대기 시점은 각 표시 자원 소유자가 유지한다. 빌드가 생성한 시간순 전환 목록은 반복되는 영토 상태와 물리 상태를 카탈로그 인덱스로 참조한다. 승인된 안정 프레임 이후 실제 변화 구간과 화면의 청크 집합을 기준으로 이동 방향의 인접 전환 상태를 우선해 최대 24MiB의 추정 준비량(대기 작업 예산의 1/2 이하)을 낮은 우선순위로 미리 읽는다. 전경 작업이 남아 있으면 유휴 알림을 기다린다. 역사 카탈로그의 선제 취득은 별도로 대기 작업 예산의 1/2 이하로 제한한다. 이웃 시점의 완료 패킷은 장치 규모에 따른 최대 12MiB의 별도 로컬 LRU 보존량으로 관리하되 공통 예산이 부족하면 퇴출할 수 있다. 이동·전환·프로젝트 교체는 추측 작업을 취소하며 추측 결과 자체는 화면을 게시하거나 자원 퇴출을 방해하지 않는다.

Core 준비 이력은 정규화된 날짜 문자열과 별도로 최소 달력 키만 색인하며, 변경 이벤트는 날짜·카탈로그 순번의 정렬된 배열로 관리한다. 연속 형상 존속 구간의 활성 객체 검색에는 최대 종료일을 가진 구간 트리를 사용한다. 원래 객체 순서 및 포함 경계는 유지한다. 동일한 불변 이력의 이벤트 없는 구간은 해석 결과를 공유하고, 큰 날짜 이동은 활성 객체 규모 및 이벤트 수 한도에 따라 재구성 경로를 택한다. JS 읽기 모델의 source-binding 구간 증명은 불변 구간 트리에서 변경된 잎만 갱신한다. Worker의 개별 요청에 대한 시간 진단은 상위 8개만 유지한다. 필수 활성 형상 및 원자적인 경계 갱신은 임의로 잘라내지 않는다.
